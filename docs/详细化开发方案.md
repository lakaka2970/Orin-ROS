#### 1.4.2 各层软件组件

| 层 | 组件 | 文件 | 功能 |
|----|------|------|------|
| **用户态: 雷达配置** | `carkit88c0_gmsl_example` | `src/demo_app/.../example/main.c` | SPI-over-GMSL 配置 CTRX 寄存器: TX功率、RX增益、RF频率、Sequencer 加载、启动连续 chirp 发射 |
| **用户态: Sequencer** | `sequencer_data.c` | `.../example/sequencer_data.c` | 43-word 时序程序: 25MSps ADC, 512 ramps/chirp, 定义 chirp 时序 |
| **内核态: GMSL 驱动** | `max929x.ko` | `src/modules/max929x/max929x.c` | I2C 驱动, probe 时配置 MAX9296+MAX96717: MIPI PHY、lane 映射、Double Mode(12→24bit打包)、GPIO隧道、SPI隧道、CSI输出 |
| **内核态: 雷达 V4L2** | `radar.ko` | `src/modules/radar/radar.c` | Tegra Camera Framework sub-device, 注册 V4L2 `/dev/videoN`, 定义 20 种采集模式 |
| **内核态: VI 框架** | `tegra-video` | NVIDIA 闭源 | MIPI CSI-2 硬件采集, DMA→内核buffer, V4L2 mmap streaming |
| **用户态: 数据采集** | `v4l2-ctl` | v4l-utils 包 | `VIDIOC_S_FMT` 设置格式 → `REQBUFS`+`mmap` → `STREAMON` → `DQBUF`(阻塞) → `write()` 到 `.bin` |
| **用户态: ROS2 实时** | `adc_rx.cpp` | `src/ft_rx_cpp/src/adc_rx.cpp` | 实时 V4L2 mmap 采集, 阻塞 `DQBUF`, 逐帧发布 `/adc/raw_data` |
| **用户态: ROS2 离线** | `adc_rx.py` / `adc_rx_analog.cpp` | `src/ft_framework/` / `src/ft_rx_cpp/` | 从 `.bin` 文件预加载帧, ctrx0+ctrx1 双文件逐帧拼接为完整 32 MiB |

#### 1.4.3 V4L2 帧格式与 .bin 文件布局

```
V4L2 帧参数 (单个 CTRX, 如 /dev/video0):
  width=8192, height=1024, pixelformat=RG12 (V4L2_PIX_FMT_SRGGB12)

每行 (8192 pixels = 16384 bytes):
  ┌──────────┬──────────┬──────────┬──────────┬──────────┬─────┐
  │ RX0_sam0 │ RX1_sam0 │ RX2_sam0 │ RX3_sam0 │ RX0_sam1 │ ... │  ← 4 RX 逐采样点交错
  │ (2bytes) │ (2bytes) │ (2bytes) │ (2bytes) │ (2bytes) │     │     RG12: 12-bit 数据 + 4-bit 零填充
  └──────────┴──────────┴──────────┴──────────┴──────────┴─────┘
  共 2048 个采样点 × 4 RX = 8192 pixels

1024 行:
  Row 0..511:   Group 0, 512 chirps (每行=1 chirp × 4 RX × 2048 samples)
  Row 512..1023: Group 1, 512 chirps
  
单帧大小 (单个 CTRX):  8192 × 1024 × 2 = 16,777,216 bytes = 16 MiB
单帧大小 (双 CTRX 合并): 2 × 16 MiB = 32 MiB

.bin 文件内容:
  [Frame0][Frame1][Frame2]...[FrameN]  ← N 帧连续拼接, 无帧头/分隔符

帧计数方式:
  n_frames = file_size / (8192 × 1024 × 2) = file_size / 16 MiB
```

#### 1.4.4 数据消费者的两种模式

| 模式 | 节点 | 数据路径 | 用途 |
|------|------|---------|------|
| **离线回放** | `adc_rx.py` / `adc_rx_analog.cpp` | `scripts/output/ctrx0_raw.bin` + `ctrx1_raw.bin` → 预加载到内存 → 逐帧拼接发布 | 算法开发、离线调试、无需雷达硬件 |
| **实时采集** | `adc_rx.cpp` | `/dev/radar_ctrx0` → V4L2 mmap `DQBUF`(阻塞) → 逐帧发布 | 实时感知、实际部署 |

> **注意**: `RSPS_main.py` 是离线信号处理调试工具，不属于 ROS2 数据流管线。ROS2 框架中 `.bin` 文件仅由 `adc_rx` 节点读取并发布为 ROS2 消息。

### 1.5 全局时间戳要求

> **所有 Rx 节点必须在数据采集第一时间注入全局统一时间戳，精度为微秒（μs）。**

时间戳贯穿整个数据链路，从采集→处理→可视化→日志，全程透传不丢失。所有输出文件以时间戳（μs）命名。

## 三、各节点详细开发需求

### 3.1 Node: ADC Rx（雷达ADC数据接收节点）

#### 基本规格

| 参数 | 值 |
|------|-----|
| 帧率 | **硬件实际频率** (轮询模式, 阻塞 V4L2 DQBUF) |
| 每组数据量 | **32 MiB** (16T16R ctrx0+ctrx1 双文件合并) |
| 数据结构 | 每 chirp **2048 个 int16 采样点**，共 **1024 chirps × 8 RX**|
| 时间戳 | ROS 系统时间 (`get_clock().now()`), 微秒精度 |

#### 数据维度解读

```
ADC 数据形状: [1024 chirps × 8 RX × 2048 samples] × int16(2 bytes)
           = (ctrx0: 512 chirps×2 groups×4 RX) + (ctrx1: 512 chirps×2 groups×4 RX)
           = 33,554,432 bytes ≈ 32 MiB
```

#### 开发任务

- [ ] **消息定义**：定义 ADC 原始数据消息类型，包含：
  ```
  std_msgs/Header header          # 含全局时间戳(μs)
  uint32 num_chirps               # 1024 (512 chirps × 2 groups)
  uint32 num_rx_antennas          # 8 (ctrx0:4 + ctrx1:4)
  uint32 num_samples_per_chirp    # 2048
  int16[] data                    # 1024×8×2048 = 16,777,216 个采样点 (ctrx0+ctrx1合并)
  ```
- [ ] **零拷贝通信**：32 MiB/帧 × 15 Hz = **480 MiB/s** 吞吐，使用 ROS2 Intra-process 或共享内存（ctrx0+ctrx1 双文件合并）
- [x] **采集频率控制**：改为轮询模式 (阻塞 V4L2 DQBUF), 频率由硬件实际发送速率决定
- [x] **时间戳注入**：在数据采集第一时间打 ROS 系统时间戳 (`get_clock().now()`)
- [ ] **缓冲区管理**：设计环形缓冲区，建议大小 ≥ 3 帧（96MB），防止处理延迟导致丢帧
- [ ] **参数化配置**：帧率、数据维度等通过 YAML 参数文件配置，支持运行时调整

### 3.3 Node: Vehicle Data Rx（车辆数据接收节点）

#### 基本规格

| 参数 | 值 |
|------|-----|
| 发布频率 | **50 Hz** (可配置, 定时器控制) |
| CAN 读取 | **独立轮询线程**, 持续读取 CAN 总线更新 buffer |
| 架构模式 | **混合模式**: CAN 读取线程 → buffer (mutex) → 定时器发布 |
| 数据内容 | 自车运动数据（ego motion） |
| 默认值机制 | 数据丢失时使用预设默认值 |
| 超时间隔 | **20ms** (1 个周期 @ 50Hz), 超过后切换为默认值 |

#### 架构说明

```
CAN Bus ──→ [CAN read thread: 持续 poll/read] ──→ buffer (mutex) ──→ [timer callback: 按 fps 发布]
```

- **CAN 读取线程**: 持续轮询 CAN 总线, 将最新数据更新到线程安全的 buffer。CAN 数据到来即更新, 不受定时器限制。
- **定时器回调**: 按 `fps` 频率 (默认 50Hz) 从 buffer 取最新数据快照, 打上 ROS 系统时间戳后发布。
- **超时检测**: 超过 `timeout_cycles` 个周期 (默认 1 周期 = 20ms) 未收到 CAN 数据, 自动切换为默认安全值。
- **未接入 CAN 时**: 定时器正常发布默认值 (`is_default=True`), CAN 线程休眠等待。

#### 开发任务

- [x] **默认值机制实现**: 已实现
- [x] **超时检测**: 已实现 (20ms 超时间隔)
- [x] **混合架构**: CAN 读取线程 + buffer + 定时器发布, `fps` 参数控制发布频率
- [x] **时间戳注入**: 使用 ROS 系统时间 (`get_clock().now()`)
- [ ] **CAN/ETH 总线接入**: 替换 `_can_read_loop()` 中的 TODO 占位为实际 CAN 读取逻辑

## 四、数据格式与消息定义（融合 FT_radar_dataset_requirement.md）

### 4.1 坐标系定义

```
        X (前方)
        ↑
        |
        |
Y ←─────● (后轴中心接地点)
        |
        |
        Z: 垂直向上 (右手坐标系)
```

| 轴 | 方向 | 正值含义 |
|----|------|---------|
| X | 车辆正前方 | 前方 |
| Y | 车辆左侧 | 左侧 |
| Z | 垂直向上 | 上方 |
| 原点 | 后轴中心接地点 | - |

**Local 坐标系**：车辆上电时的后轴中心位置，轴方向与上电时刻车辆坐标系一致。

### 4.2 雷达点云数据字段（det_list → PCD/CSV）

Logging 输出的 `det_list.csv` 和 `det_list.pod` 字段定义：

| # | 字段名 | 类型 | 单位 | 必需性 | 描述 |
|---|--------|------|------|:------:|------|
| 1 | `x` | float32 | m | **必需** | 车辆系纵向坐标（前方为正） |
| 2 | `y` | float32 | m | **必需** | 车辆系横向坐标（左侧为正） |
| 3 | `z` | float32 | m | **必需** | 车辆系垂直坐标（上方为正） |
| 4 | `range` | float32 | m | **必需** | 径向距离（雷达传感器坐标系） |
| 5 | `azimuth` | float32 | rad | **必需** | 方位角（雷达传感器坐标系） |
| 6 | `elevation` | float32 | rad | **必需** | 俯仰角（雷达传感器坐标系） |
| 7 | `RCS` | float32 | dBsm | **必需** | 雷达散射截面积，值域 [-100, 129.37] |
| 8 | `SNR` | float32 | dB | 可选 | 信噪比，值域 [0, 63.75] |
| 9 | `ambgt` | float32 | m/s | **必需** | 速度模糊窗宽（FFT多普勒最大不模糊度范围） |
| 10 | `exist_prob` | uint8 | [0,255] | **必需** | 存在概率，≥30保留，255=无效 |
| 11 | `multi_tgt_prob` | uint8 | [0,255] | 可选 | 多目标概率，255=无效 |
| 12 | `ambgt_prob` | uint8 | [0,255] | **必需** | 模糊概率，≥40保留，255=无效 |
| 13 | `raw_doppler` | float32 | m/s | **必需** | 原始多普勒径向速度（经硬件一次解模糊） |
| 14 | `idx` | uint8 | - | **必需** | 多普勒解模糊索引；255=SNA(无效)；0=解模糊失败 |

**关键过滤规则**：

| 过滤器 | 条件 | 默认阈值 |
|--------|------|----------|
| ROI | x/y/z 超出包围盒 | x∈[-80,200], y∈[-40,40], z∈[-15,15] m |
| 高度 | \|z\| >= \|x\| × 0.1 + 2 | 自适应 |
| RCS | 10m内: RCS≤-40; 10m外: RCS≤-20 | dBsm |
| 存在概率 | exist_prob < 30 | - |
| idx | idx == 255 (SNA) | - |
| 模糊概率 | ambgt_prob < 40 | - |

## 五、时间同步机制

### 5.1 全局时间戳方案

| 项目 | 规格 |
|------|------|
| 时钟源 | ROS 系统时间 `get_clock().now()` (开发阶段) / PTP硬件时钟（生产阶段） |
| 精度 | 微秒（μs） |
| 注入位置 | 所有 Rx 节点数据采集第一时间 (轮询线程/定时器回调) |
| 透传规则 | 后续节点不得覆盖，仅在消息头 `header.stamp` 中传递 |

### 5.2 多传感器时间对齐策略

- **ADC Rx**：轮询模式, 硬件实际频率 (V4L2 阻塞 DQBUF), 每帧即时 ROS 时间戳
- **Camera Rx**：轮询模式, 硬件实际频率 (阻塞 `camera.read()`), 每帧即时 ROS 时间戳
- **Vehicle Data Rx**：混合模式, CAN 读取线程持续更新 buffer, 定时器按 50Hz 发布时打 ROS 时间戳
- **Logging 对齐**：Camera/Vehicle 数据按时间戳最近邻匹配到雷达帧
- **ego_motion.csv**：单文件按时间戳排序存储，程序处理时按时间戳交替处理
