# 基于ROS2的雷达-相机-车辆数据融合感知框架——全面描述

---

## 一、系统与软件环境

框架运行在 **NVIDIA Jetson AGX Orin 64GB** 嵌入式计算平台上，具体软件栈如下：

| 项目 | 版本 |
|------|------|
| 操作系统 | Ubuntu 20.04 |
| Jetpack | 5.1.2 |
| ROS2 发行版 | Humble |

软件开发遵循 **ROS2 src guideline**（ROS2源码开发规范）。

> **上电顺序要求**（图中顶部黄色注释）：**Radar（雷达）和 Camera（相机）先上电，然后再启动 Orin 计算平台。**

---

## 二、节点（Node）总览

整个系统共包含 **10个ROS2节点**，分布在四个逻辑层级中，通过 **pub（发布）** 和 **sub（订阅）** 机制进行通信。红色方块标注的 **pub** 表示该节点对外发布话题（topic），红色方块标注的 **sub** 表示该节点订阅外部话题。

---

## 三、各节点详细描述

### 第一层：数据采集层（3个接收节点）

#### 1. Node: ADC Rx（雷达ADC数据接收节点）

- **内部组件**：`cfg, init`（配置与初始化模块）→ `v4l2`（Video4Linux2驱动接口）→ `ADC`（圆柱形数据库/缓冲区，存储雷达原始ADC数据）
- **功能**：通过v4l2接口从雷达硬件采集原始ADC（模数转换）数据，经配置初始化后存入ADC数据缓冲区
- **发布（pub）**：将ADC数据发布出去
- **连接关系**（箭头指向）：
  - → **Node: R SP MIL Python** 的 sub（订阅端）
  - → **Node: R SP Cuda** 的 sub（订阅端）
  - → **Node: Logging** 的 sub（订阅端）

---

#### 2. Node: Camera Rx（相机数据接收节点）

- **内部组件**：`cfg, init`（配置与初始化模块）→ `v4l2`（Video4Linux2驱动接口）→ `Video`（圆柱形数据库/缓冲区，存储视频数据）
- **功能**：通过v4l2接口从相机硬件采集视频帧数据，存入Video数据缓冲区
- **发布（pub）**：将视频数据发布出去
- **连接关系**（箭头指向）：
  - → **Node: Rviz_Image** 的 sub（订阅端）
  - → **Node: Logging** 的 sub（订阅端）

---

#### 3. Node: Vehicle Data Rx（车辆数据接收节点）

- **内部组件**：`cfg, init`（配置与初始化模块）→ `CAN/ETH`（CAN总线/以太网通信接口）→ `vdd`（圆柱形数据库/缓冲区，存储车辆动态数据）
- **功能**：通过CAN总线或以太网接收车辆动态数据（如车速、航向角等），存入vdd数据缓冲区
- **发布（pub）**：将车辆数据发布出去
- **连接关系**（箭头指向）：
  - → **Node: R SP MIL Python** 的 sub（订阅端）
  - → **Node: R SP Cuda** 的 sub（订阅端）
  - → **Node: Logging** 的 sub（订阅端）

---

### 第二层：雷达信号处理层（2个并行处理节点）

#### 4. Node: R SP MIL Python（雷达信号处理——Python/MIL实现节点）

- **内部组件**：`ADC`（雷达ADC数据）+ `vdd`（车辆动态数据）→ `rsp_py`（Python实现的雷达信号处理算法）→ `Det List`（圆柱形数据库，存储检测目标列表）
- **功能**：使用Python/MIL（Matrix Laboratory风格）方式实现雷达信号处理，融合ADC数据和车辆数据，**解决速度模糊问题（solving velocity ambiguity）**，输出检测目标列表（Det List）
- **订阅（sub）**：接收来自 ADC Rx 和 Vehicle Data Rx 的数据
- **发布（pub）**：将Det List发布出去
- **连接关系**（箭头指向）：
  - → **Node: Rviz_radar** 的 sub（订阅端）
  - → **Node: 3D Object Detection** 的 sub（订阅端）
  - → **Node: Logging** 的 sub（订阅端）

---

#### 5. Node: R SP Cuda（雷达信号处理——CUDA加速实现节点）

- **内部组件**：`ADC`（雷达ADC数据）+ `vdd`（车辆动态数据）→ `rsp_cu`（CUDA实现的雷达信号处理算法）→ `Det List`（圆柱形数据库，存储检测目标列表）
- **功能**：使用CUDA GPU加速方式实现雷达信号处理，同样融合ADC数据和车辆数据，**解决速度模糊问题（solving velocity ambiguity）**，输出检测目标列表（Det List）。与R SP MIL Python为**并行/替代方案**，提供GPU加速版本
- **订阅（sub）**：接收来自 ADC Rx 和 Vehicle Data Rx 的数据
- **发布（pub）**：将Det List发布出去
- **连接关系**（箭头指向）：
  - → **Node: Rviz_radar** 的 sub（订阅端）
  - → **Node: Logging** 的 sub（订阅端）

---

### 第三层：可视化与日志层（3个节点）

#### 6. Node: Rviz_radar（雷达数据RViz可视化节点）

- **内部组件**：`det_list`（检测目标列表）+ `obj_list`（3D目标列表）→ `rviz`（RViz可视化工具）
- **功能**：在RViz中可视化雷达检测结果，同时显示det_list（雷达点云/目标检测列表）和obj_list（3D物体识别结果列表）
- **订阅（sub）**：接收来自多个节点的数据
- **连接关系**（箭头来源）：
  - ← **Node: R SP MIL Python** 的 pub（订阅其Det List）
  - ← **Node: R SP Cuda** 的 pub（订阅其Det List）
  - ← **Node: 3D Object Detection** 的 pub（订阅其obj_list）
  - ← **Node: Rviz_Ruler** 的 pub（订阅ruler标尺数据）

---

#### 7. Node: Rviz_Image（图像RViz可视化节点）

- **内部组件**：`video`（视频数据）→ `rviz`（RViz可视化工具）
- **功能**：在RViz中可视化相机采集的视频图像
- **订阅（sub）**：
  - ← **Node: Camera Rx** 的 pub（订阅其Video数据）

---

#### 8. Node: Logging（数据日志记录节点）

- **内部组件**：`ADC` + `video` + `Det List` + `vdd` → `log`（日志记录模块）→ 输出四个文件：
  - `adc.bin`（雷达ADC原始数据二进制文件）
  - `video.mp4`（相机视频MP4文件）
  - `det_list.csv`（检测目标列表CSV文件）
  - `vdd.csv`（车辆动态数据CSV文件）
- **功能**：集中记录所有传感器数据和检测结果，用于离线分析和回放
- **订阅（sub）**：接收来自几乎所有上游节点的数据
- **连接关系**（箭头来源）：
  - ← **Node: ADC Rx** 的 pub
  - ← **Node: Camera Rx** 的 pub
  - ← **Node: Vehicle Data Rx** 的 pub
  - ← **Node: R SP MIL Python** 的 pub
  - ← **Node: R SP Cuda** 的 pub

---

### 第四层：高级感知与辅助层（2个节点）

#### 9. Node: 3D Object Detection（3D目标检测节点）

- **内部组件**：`det_list`（雷达检测目标列表）→ `AI Model`（AI深度学习模型）→ `obj_list`（圆柱形数据库，存储3D目标识别结果列表）
- **功能**：基于雷达检测列表（det_list），利用AI模型进行3D目标检测与分类，输出包含3D位置、类别等信息的目标列表（obj_list）
- **订阅（sub）**：
  - ← **Node: R SP MIL Python** 的 pub（订阅其Det List）
- **发布（pub）**：将obj_list发布出去
- **连接关系**（箭头指向）：
  - → **Node: Rviz_radar** 的 sub（将3D目标结果送可视化）

---

#### 10. Node: Rviz_Ruler（RViz标尺/参考节点）

- **内部组件**：`ruler`（圆柱形数据库，存储标尺/参考坐标系数据）
- **功能**：提供RViz可视化所需的标尺或参考基准数据（如距离标尺、坐标参考等）
- **发布（pub）**：将ruler数据发布出去
- **连接关系**（箭头指向）：
  - → **Node: Rviz_radar** 的 sub（为雷达可视化提供参考标尺）

---

## 四、数据流总览

```
[ADC Rx] ──pub──→ [R SP MIL Python] ──pub──→ [3D Object Detection] ──pub──→ [Rviz_radar]
    │                    │                        ↑
    ├──pub──→ [R SP Cuda] ─pub───────────────────┘
    │
    └──pub──→ [Logging] ←──pub── [Camera Rx] ─pub──→ [Rviz_Image]
                        ↑
[Vehicle Data Rx] ──pub──┘
                        ↑
[Rviz_Ruler] ──pub──────→ [Rviz_radar]
```

**核心数据流向**：
1. **三条数据输入流**：雷达ADC数据、相机视频数据、车辆CAN/ETH数据分别由三个Rx节点采集
2. **双路径雷达信号处理**：ADC数据 + 车辆数据同时送入Python版和CUDA版两个并行处理节点，均执行速度模糊消除，生成Det List
3. **3D目标检测**：Python版Det List进一步送入AI模型生成3D目标列表
4. **统一可视化**：Rviz_radar汇聚det_list、obj_list和ruler进行综合显示；Rviz_Image独立显示视频
5. **全量日志**：Logging节点收集所有原始数据和中间结果，输出为bin/mp4/csv文件供离线分析
